# Porting brief for one grammar (read fully before starting)

You port ONE tree-sitter grammar (or one small family of grammars from one crate) into this
pure-Rust multi-tier crate. The ten medium-tier grammars (lua, dart, cpp, c_sharp, scala, kotlin,
ruby, swift, bash, php) are finished examples: read `CONTRIBUTING.md` ("Adding a language to a
tier"), `tools/regen.sh`, `tools/verify.sh`, `tools/register.py`, and one finished module with a
scanner (`src/bash`, `src/lua`) with its `tests/<name>.rs`. Follow them exactly. In the text below
`<name>` is your module name (also the feature `lang-<name>`).

## Isolation (other agents run at the same time)
1. Work ONLY in your own worktree:
   `git -C /Users/enzo/Code/tree-sitter-grammars-rs worktree add /Users/enzo/Code/tsg-wt-<name> -b port-<name>`.
   Never edit /Users/enzo/Code/tree-sitter-grammars-rs itself, never touch other `tsg-wt-*`
   directories, never push, never switch branches there.
2. The c2rs harness writes into its own directory: make a private copy
   `rsync -a --exclude target /Users/enzo/Code/c2rs/ /private/tmp/claude-501/tsg-c2rs-<name>/` and run
   with `C2RS=/private/tmp/claude-501/tsg-c2rs-<name>` ... `$C2RS/run.sh`. The transpiler
   `/Users/enzo/Code/c2rs/target/release/c2rs` is read-only and shared. Use a private `LITE_DIR`
   under `/private/tmp/claude-501/tsg-work-<name>/`.
3. When done, delete every `target` directory you created and your scratch directories (disk is
   tight). Long commands (transpile, rustfmt, C compile of a multi-million-line parser.c) can take
   many minutes: run them in the background and wait, never abandon a step because it is slow.

## Steps
1. Source: the unpacked crate in `~/.cargo/registry/src/index.crates.io-*/<crate>-<version>` named in
   your parameters. If its `parser.c` is ABI 15 in the current layout, try `emit` (c2rs on the shipped
   parser.c). If it is ABI 13 or 14 (or c2rs rejects it) REGENERATE at ABI 15 with
   `tree-sitter generate --abi 15 src/grammar.json` (CLI 0.26.7) exactly as the `regen` function of
   `tools/regen.sh` does (it needs a `tree-sitter.json`; the function writes one). A crate without
   `src/grammar.json` (vendored grammars): clone the upstream repository named in its
   Cargo.toml/README at the matching version or commit, and take `src/grammar.json` from there; state
   in your report exactly what you used. Grammars whose parser.c is not under `src/` (for example
   `grammar-src/` or `grammars/<x>/src/`) need the same treatment by hand.
2. Transpile to `src/<name>/parser.rs` (drop the generated abi.rs, set the header line to
   `//! Generated by c2rs. Do not edit.`, `rustfmt --edition 2024`). Note the symbol parser.c really
   exports: if it is not `tree_sitter_<name>`, pass the export name (see the optional argument of
   `emit`/`regen` in tools/regen.sh and `--export` of register.py).
3. If the grammar has an external scanner: hand-port it to `src/<name>/scanner.rs`. Faithful
   translation: same control flow, integer widths and wrapping, exported symbols
   `tree_sitter_<prefix>_external_scanner_{create,destroy,serialize,deserialize,scan}`,
   `#![allow(clippy::all, unsafe_op_in_unsafe_fn)]`. Rules learned on the earlier grammars:
   - `iswspace`, `iswalpha`, `iswalnum`, `iswdigit`, `iswlower`, `iswupper`, `isdigit`... are
     ported as the C locale (ASCII only). List every use in your report; never guess Unicode.
   - Where the C serializer or any other code can write or read out of bounds, do NOT copy the
     overrun: check the real bound (it must give the same result wherever the C stays in bounds)
     and say so in a comment and in your report.
   - A C `assert` that only fires on corrupt input may become a `debug_assert!`.
   - Keep serialized bytes identical to the C (native endianness, same layout).
   - If the C reference scanner crashes in the harness inside an `array_delete`/`array_pop` macro
     usage, the generator-written `src/tree_sitter/array.h` is the cause: replace it in the C source
     copy with the crate's own shipped `array.h` (regen.sh already preserves it).
   If there is no scanner, there is no scanner.rs (like go or java).
4. `src/<name>/mod.rs`: `LANGUAGE` (or the constant name the upstream crate uses) and every data
   constant the upstream `bindings/rust/lib.rs` exports under the SAME names; data files into
   `data/<name>/`; copy the upstream `LICENSE` file into `data/<name>/LICENSE` (if the crate lacks
   one, fetch it from the upstream repository with `gh api repos/<owner>/<repo>/license --jq .content
   | base64 -d`).
5. Register: `python3 tools/register.py <name> --tier full --const <CONST> --crate <crate-dir>
   --mode emit|regen [--subdir <d>] [--export <suffix>]` in your worktree (idempotent). It edits
   Cargo.toml, src/lib.rs, tools/regen.sh and tools/verify.sh: you need them to build and test, but
   DO NOT commit those four files. If the script cannot express your layout, edit regen.sh/verify.sh
   by hand and put the exact `git diff -- tools/` in your report so I can apply it.
6. Verify against the C with the harness: `LITE_DIR=.. PREGEN=<dir with abi.rs (copy of src/abi.rs)
   and your parser.rs> RS_SCANNER=<your scanner.rs, if any> DIRECT=1 GOLDEN=<file> SOUP=8000 FUZZ=10
   PREFIX=12 INCR=5 [C_INC=<shared include dir>] $C2RS/run.sh <harness name = export suffix> <C src dir
   (the REGENERATED src for regen-mode grammars)> <corpus dir or -> - <ext>`. The corpus is the
   upstream repo's `test/corpus` at the matching tag (git clone --depth 1; if missing pass `-` and say
   so). It must end `RESULT: PASS` with 0 mismatches everywhere. Fix causes in your scanner port,
   never in the inputs. Record `tests/golden/<name>.golden` (more than 150 cases; a record can
   contain a newline in its tree, see how tests/dart.rs reads golden files).
7. `tests/<name>.rs` modelled on tests/lua.rs / tests/bash.rs: a smoke parse from real syntax that
   exercises the scanner, the golden trees, and that every bundled query compiles.
8. `cargo fmt --all`; `cargo clippy --all-targets --no-default-features --features lang-<name> --
   -D warnings`; `cargo test --release --no-default-features --features lang-<name>`; `cargo build
   --release --no-default-features --features lang-<name>` must all pass.
9. Commit ONLY `src/<name>/`, `data/<name>/` (including its LICENSE), `tests/<name>.rs`,
   `tests/golden/<name>.golden` (explicit `git add` paths) on branch `port-<name>` with a message
   ending in the line `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Leave the four shared
   files uncommitted.

## Report (concise and factual; do not claim what you did not run)
The final `RESULT:` line and counters (direct lexer calls, scanner scans, corpus, prefixes,
incremental, soup, fuzz), the golden count, the exact register.py command, scanner line counts (C vs
Rust), parser.rs size, the licence's copyright line, every judgement call (locale functions,
out-of-bounds, source used when something was missing), anything that failed, the `git diff -- tools/`
if you hand-edited tools, and the worktree path.
